# FlowFreeze: fix guide (what changed, where, and what to say to judges)

## Run order (≈1 min)
1. `pip install -r requirements.txt`
2. `python -m data_generator.generate_transactions` → 20k tx, overlapping fraud/legit, label noise
3. `python -m ml.train_fraud_model` → writes `models/*.joblib`, `data/processed/evaluation.json`, `impact.json`
4. `python -m pytest -q tests`
5. `export FLOWFREEZE_DEMO_MODE=true FLOWFREEZE_API_TOKEN=demo-analyst-token` (local demo only), `uvicorn backend.main:app --port 8000`
6. `npm install && npm run build && npm start`

| # | Problem (judge's view) | Fix | Files |

## Current results (seed 42; regenerated by step 3)
- Fraud model (time-held-out): ROC-AUC 0.948, PR-AUC 0.715 (chance 0.068). Logistic regression PR-AUC 0.548; fixed rules recall 19% vs FlowFreeze 67%.
- Alert-rate on legitimate traffic is 2.7% on test (2% was the validation target).
- Next-move: accuracy 87.2% vs majority 85.8% (modest); cash-out PR-AUC 0.42 vs 0.08 base rate.
- Impact (5-min analyst delay): FlowFreeze preserved 55.6% of fraud value vs 49.6% for rules (+12%), caught 67 vs 41 episodes, but raised more false alerts (82 vs 52). Proportional holds freeze ~96% less legitimate value than whole-wallet holds. Speed matters: 76% preserved at ≤2 min, 36% at 10 min.
- Fairness finding: false-alert rate is higher for new accounts (7.7% vs 2.6%) and the agent channel (7.6% vs ~2%). Reported, not hidden.
