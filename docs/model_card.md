# FlowFreeze model card

## Models

FlowFreeze trains two persisted scikit-learn `RandomForestClassifier` artifacts from the labeled behavioral dataset generated by `python -m data_generator.generate_transactions`: `models/fraud_model.joblib` predicts `P(is_fraud)` and `models/next_move_model.joblib` predicts `P(next_action)` for `forward`, `cashout`, and `other`.

Fraud labels are assigned from scenario ground truth, not from the `cashout_flag` feature. Legitimate scenarios include merchant activity and unusual personal activity, including some cash-outs. Next-action labels are generated as behavioral outcomes separately from the fraud label.

## Reproducible training

```bash
python -m data_generator.generate_transactions
python -m ml.train_fraud_model
```

The training command performs a stratified 75/25 train/test split, persists both models, and writes held-out precision, recall, F1, false-positive/false-negative counts, ROC-AUC, next-action accuracy, and fairness slices to `data/processed/evaluation.json`. The notebooks execute the same pipeline.

## Inference contract

The API loads the joblib artifacts and refuses to infer if they are absent. It accepts transaction-specific behavioral features: amount, sender/receiver velocity, cash-out status, new relationship, rapid forwarding, amount-vs-average, hour, account age, device change, merchant flag, and channel. No risk or next-action probability is hard-coded.

This is a synthetic demonstration model. It is not production performance evidence; real deployment requires representative, consented labels, time-based validation, calibration monitoring, drift checks, and an operations-approved threshold.
